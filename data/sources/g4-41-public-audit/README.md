# G411/G414 公开来源核对

本目录保存 2026-10-01 获取的设备包描述及 ST HAL 来源，完整版本、URL、长度和 SHA-256 见 `sources.json`。DFP 与 ST HAL 的原始许可证随来源保存；CMSIS 头文件复用 `../stm32-gaps/` 中固定的 ST 版本，逐文件哈希记录在 `memory-audit.json`。

核对覆盖目录中的 23 个准确型号和 DFP 的 32 个订货条目。结果用于发现冲突，尚未生成 PAC、接入 HAL 或确认器件限制。

| 分组 | CMSIS 宏给出的 RAM 上限合计 | DFP 连续 SRAM 区域 | pin XML 的 RAM 值 |
|---|---:|---:|---:|
| G411 的 6/8/B 容量型号 | 32 KiB | 32 KiB | 32 KiB |
| G411 的 C 容量型号 | 112 KiB | 112 KiB | 256 KiB |
| G414 | 60 KiB | 128 KiB | 256 KiB |

CMSIS 的 `SIZE_MAX` 是上限，不能独自证明每个订货型号的可用容量、别名与保留区。DFP 为 G411/G414 分别指向 G431/G474 的调试 SVD；这也不能证明两组器件具有相同寄存器或外设。尤其不能把 G414 的 128 KiB 直接写入正式链接布局。表中的 XML 值来自固定 pin 快照生成的型号目录；离线命令复核原始 CMSIS/DFP 与捕获结果，不重新生成 XML 目录。

```powershell
. .\scripts\env.ps1
python data/sources/g4-41-public-audit/verify.py
```

当前保留 8 个 G414 的 CMSIS/DFP RAM 冲突。工作频率、供电、Flash 擦写/延迟、外设裁剪与勘误仍需准确器件资料，内存数字一致也不代表完成适配。

## 2026-10-03 用户提供的三份手册

已核对本地 PDF 的版本、SHA-256、适用范围，并检索全部 2,638 页；文件信息和检查结果见 [资料核对记录](user-manual-review-20261003.json)。原始 PDF 保留在用户提供的路径，未复制进仓库，也不是构建或 CI 的依赖。六页关键表格的渲染检查图位于 `target/g4-user-manual-review-v1/`，共约 1.23 MB。

| 资料 | 版本 | 可以证明的范围 | 对 G411/G414 的限制 |
|---|---|---|---|
| STM32G4 参考手册 RM0440 | Rev 9，2025-03，2,140 页 | 第 75 页表 1 列出的 G431/441/471/473/474/483/484/491/4A1；第 88 页 SRAM；第 437–440 页中断表 | 产品分类表未包含 G411/G414，不能据分类容量或外设超集填补这两组器件 |
| G474 数据手册 DS12288 | Rev 6，2021-11，236 页 | G474xB/xC/xE；第 2 页的 18 个型号与项目 G474 目录一致 | 只覆盖 G474，不能裁决 G414 的 60/128/256 KiB RAM 冲突 |
| Cortex-M4 编程手册 PM0214 | Rev 10，2020-03，262 页 | 指令、异常、NVIC 等内核机制 | 不提供准确器件的 RAM 容量、外设裁剪、供电和 Flash 限制 |

现有 **18 个 G474 型号的 RAM 元数据**与 DS12288 第 20 页一致：SRAM1 为 80 KiB，地址 `0x20000000`；SRAM2 为 16 KiB，地址 `0x20014000`；CCM 为 32 KiB，地址 `0x10000000`，同时别名映射到 `0x20018000`。CCM 两个地址指向同一块物理 RAM，总容量为 128 KiB，不能重复相加。STM32G474CE 示例在核对时绑定的 **11 个 IRQ 编号**也与 RM0440 表 100 一致；这次核对未覆盖所有寄存器、引脚或实机行为。

PM0214 第 39 页的通用说明提到 IRQ0–IRQ81，而 RM0440 的器件中断表包含高于 81 的编号；不能用该通用说明截断器件向量表。三份资料全文均未出现 G411/G414，且适用范围不能支持将它们映射为相近芯片。因此 **23 个后端缺口及既有 RAM 冲突保持未解决**。本次未修改驱动或支持状态，未重新构建固件，也未执行 HIL。
